## 4. 本简历的取舍规则

**优先写**（面试最能展开）：
1. 禁忌拦截：慢病 × 忌口 × 吞咽等级的决策表，坚果餐单下发给吞咽障碍老人（有安全属性，最值钱）
2. AI 生成质量：黄金样例 200 条 + 结构化断言，72% → 96%
3. 名额超卖 + 并发：JMeter 300 并发 → 日志定位 → Redis 预扣 + DB 唯一约束兜底
4. 退款分摊：3 券叠加 × 部分退，按实付比例重算，500 单差异为 0
5. 支付回调幂等：抓包重放 30 次，重复占位 + 重复短信
6. 接口自动化 52 个 + Jenkins，回归 180 → 55 分钟

**弱化**：
- UI 自动化（本版已删除 Playwright，不要再加回）
- 安全测试（不再出现 SQLMap 战绩）
- 造数脚本（只在工作经历一句带过）

**禁止**：
- Rust 及“自研压测工具”
- 进销存 / ETL / CRM 旧项目名
- “精通”
- 把旅游业务写成“电商商城秒杀”
- 同时写两个 OTA 项目（会显得重复，也会把 AI 经历淹掉）

## 5. 正式版 vs 线上版

- `site_full_show.md`：可写满，条目多、技术细节全，供 HR 与面试官细读。
- `resume_3y_oneline.md`：**不单列项目经历**，项目成果并入工作经历，每条只留结论 + 数字，第一屏必须出现岗位/年限/城市/学历/状态。
- 两版**数字与时间线必须完全一致**；改一版必须同步另一版。

## 6. 数字口径备注

- 用例：项目 1 写 **280 + 条**，项目 2 写 **420 + 条**；工作经历不另写总数，避免出现第三个口径。
- 高危缺陷：项目 1 **6 个** + 项目 2 **6 个** = 个人优势段 **12 个**，三者必须始终对得上。
- 全局只出现一次的量：**300 并发**、**200 次回归**、**30 次回调重放**、**50 次生成**、**200 组禁忌组合**、**180 → 55 分钟**。
- 采购量差 5% – 8% 是“未解决项”，用来制造真实感，不要改成“已修复”。
